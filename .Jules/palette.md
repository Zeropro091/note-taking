## 2024-05-14 - Icon Button Accessibility and Hover States\n**Learning:** Icon-only buttons often lack `aria-label`s for screen reader support, and elements hidden behind `group-hover` states become inaccessible to keyboard navigation if `focus-visible` states aren't also applied. Missing the `group` class on the parent container also breaks the hover state entirely.\n**Action:** Always pair `group-hover:opacity-100` with `focus-visible:opacity-100` for interactive elements, and verify the parent container has the `group` class. Add descriptive `aria-label`s to all icon-only buttons.

## 2024-05-25 - Overlay Toggle Buttons and Interactive Elements
**Learning:** Toggle buttons (like tag filters) and controls within custom overlays (like an info panel in a canvas view) often lack `aria-pressed` states and `focus-visible` rings because they exist outside the main document flow or use custom container styling. This makes screen reader feedback confusing and keyboard navigation visually untraceable.
**Action:** When implementing custom filter toggles or overlay controls, always explicitly define `aria-pressed` based on the active state, and add `focus-visible:outline-none focus-visible:ring-2` to guarantee a visible focus indicator for keyboard users.
