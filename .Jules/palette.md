## 2024-05-14 - Icon Button Accessibility and Hover States\n**Learning:** Icon-only buttons often lack `aria-label`s for screen reader support, and elements hidden behind `group-hover` states become inaccessible to keyboard navigation if `focus-visible` states aren't also applied. Missing the `group` class on the parent container also breaks the hover state entirely.\n**Action:** Always pair `group-hover:opacity-100` with `focus-visible:opacity-100` for interactive elements, and verify the parent container has the `group` class. Add descriptive `aria-label`s to all icon-only buttons.

## 2024-06-23 - Accordion Group Accessibility and Keyboard Navigation
**Learning:** Accordion-style collapsible groups in the sidebar lacked proper ARIA attributes linking the toggle button to the content container, hindering screen reader users. Additionally, relying solely on hover states made keyboard navigation difficult. Spaces in dynamic group names break `aria-controls` which expects a space-separated list of IDs, so sanitization is critical.
**Action:** Always pair `aria-expanded` and `aria-controls` on toggle buttons with a matching `id` on the content container, sanitizing strings (e.g., `.replace(/\s+/g, '-')`) before using them as IDs. Consistently add `focus-visible:outline-none focus-visible:ring-2` to interactive list items and accordion headers to ensure visible keyboard focus indicators.
