## 2024-06-18 - Optimize GraphView edge filtering and computation
**Learning:** Performing `find()` lookups within an edge loop (`filter()` or `map()`) leads to `O(N*E)` time complexity, which is a significant performance bottleneck in data-heavy components. Furthermore, re-calculating derived states like graph data arrays or list of unique tags without memoization can cause exhaustive-deps warnings and severe rendering lags during frequent user interactions (like hover/zoom).
**Action:** When filtering links based on node properties, pre-compute a `Set` of valid node IDs (`O(N)`) before the loop, enabling `O(1)` lookups per edge and reducing overall complexity to `O(N+E)`. Always wrap expensive derived calculations like graph objects in a `useMemo` hook to prevent redundant calculations across renders.
