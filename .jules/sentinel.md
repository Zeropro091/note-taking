## 2024-11-20 - Path Traversal Bypass via Backslash Normalization
**Vulnerability:** A path traversal vulnerability existed in `validateNoteId` where Windows-style directory separators (`\`) could bypass traversal checks because `path.relative` on non-Windows environments might not properly handle them as directory boundaries, or if normalization to forward slashes (`/`) happened *after* the validation step, allowing payloads like `..\\..\\etc\\passwd` to pass.
**Learning:** Normalizing input to a standard format (e.g., converting backslashes to forward slashes) must occur *before* any security validation checks are applied, otherwise the validation logic may misinterpret the input or miss malicious patterns.
**Prevention:** Always normalize file paths and identifiers to a consistent format (like using strictly forward slashes) before performing boundary checks like looking for `..` or validating with `path.relative`. Additionally, explicitly reject sequences like `..` as a defense-in-depth measure rather than relying solely on path resolution behaviors.
