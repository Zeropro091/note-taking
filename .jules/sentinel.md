## 2025-07-07 - Path Traversal Vulnerability in `validateNoteId`
**Vulnerability:** The `validateNoteId` function was vulnerable to path traversal attacks using Windows-style backslashes (`\`) combined with `path.relative` when running on a POSIX system (like Linux). Because `path.resolve` and `path.relative` use POSIX rules on Linux, backslashes are not treated as path separators. The input `..\..\etc\passwd` would bypass validation, and later `sanitizeNoteId` would replace backslashes with forward slashes (`/`), effectively enabling the traversal during file operations.
**Learning:** Normalizing backslashes to forward slashes *must* occur BEFORE path resolution and validation. A defense-in-depth approach is also required to reject `..` traversal attempts explicitly, avoiding broad `.includes('..')` checks which falsely reject valid filenames (e.g. `my..note`), instead using bounded regex `/(^|\/)\.\.(?=\/|$)/`.
**Prevention:** Always normalize path separators before validating paths, especially in environments where code might run on different operating systems or process mixed path styles. Reject suspicious path components explicitly rather than relying solely on `path.relative`.
