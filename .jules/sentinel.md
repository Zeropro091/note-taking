## 2025-01-20 - Path Traversal Bypass via Input Modification After Validation
**Vulnerability:** A critical path traversal bypass was discovered in `validateNoteId` where Windows-style backslashes (`\`) were treated as literal filename characters on Posix systems by `path.resolve`. This meant an input like `..\..\etc\passwd` would pass `validateNoteId`, but subsequently be transformed by `sanitizeNoteId` (which replaced `\` with `/`) into `../../etc/passwd`, allowing traversal out of the notes directory when `getNoteById` or `saveNote` ultimately used it.
**Learning:** Never validate one string and then silently modify it into another string before resolving the path. If input must be normalized (e.g., converting backslashes to forward slashes to handle Windows/Unix discrepancies securely), it MUST happen *before* the path validation/resolution step.
**Prevention:** Always normalize path separators to a consistent format (`/`) immediately before passing the input to `path.resolve` or `path.relative`. Additionally, employ defense-in-depth by explicitly rejecting the exact substring `..` bounded by path boundaries `/(^|\/)\.\.(?=\/|$)/` to catch logical bypasses where standard API pathing (like `path.relative`) might otherwise resolve safely but dangerously within the context of unexpected modifications.
