## 2026-06-06 - POSIX Path Traversal Bypass via Backslashes
**Vulnerability:** A path traversal vulnerability existed in `validateNoteId` where user-supplied IDs were directly passed to `path.resolve`. While the code checked if the resulting relative path started with `..`, it was possible to bypass this on POSIX systems by using backslashes (e.g., `..\..\etc\passwd`). On POSIX, `path.resolve` treats `\` as a regular character in the filename, not a directory separator. This caused `path.relative` to think the file was within the correct directory, returning `true` for `validateNoteId`. Later in the application lifecycle or via other utilities that normalize paths differently, this bypass could have been exploited to read or write arbitrary files. Additionally, the application attempted to simply sanitize paths containing `..` rather than explicitly rejecting them.
**Learning:** `path.resolve` and `path.relative` behavior differs significantly between POSIX and Windows environments. On POSIX, backslashes are valid filename characters and are not interpreted as path separators. Relying solely on `path.resolve` followed by `path.relative` without first normalizing backslashes allows traversal strings to sneak past the validation logic on Linux/Mac environments.
**Prevention:** Always explicitly reject any paths containing traversal sequences (`..`) as a defense-in-depth measure. Furthermore, explicitly normalize all backslashes (`\`) to forward slashes (`/`) *before* passing the untrusted input to path manipulation functions like `path.resolve` to ensure consistent path evaluation across all OS environments.
