## 2024-06-04 - Fix Path Traversal Vulnerability in Note ID Validation
**Vulnerability:** The application was susceptible to path traversal attacks via note IDs because backslashes `\` were not normalized into forward slashes `/` before using `path.resolve`. On Linux-based environments, POSIX `path.resolve` handles backslashes like regular characters rather than path separators. This could allow an attacker to create files with backslashes in the filename (e.g., `..\\..\\etc\\passwd`) that might later be parsed in an unintended manner by Windows or by other filesystem wrappers. Additionally, although `path.relative` might verify the path doesn't escape the expected directory on the local system, treating `..` as a valid token is generally unsafe and bypassable depending on the host OS.
**Learning:** `path.resolve` behaves differently depending on the operating system. On a POSIX system, `path.resolve` treats backslashes differently from how Windows treats them. Relying solely on `path.resolve` and `path.relative` without prior normalization of mixed separators (like backslashes) leaves room for potential path traversal bypasses.
**Prevention:** Always normalize backward slashes to forward slashes before resolving and evaluating paths. As a defense-in-depth measure, explicitly reject occurrences of `..` in user-provided IDs even if the resolved relative path initially appears safe.
