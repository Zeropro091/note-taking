## 2024-07-01 - POSIX Path Traversal Bypass via Backslashes
**Vulnerability:** A path traversal vulnerability existed in `validateNoteId` where Windows-style backslashes (`\`) could be used to bypass path traversal checks. The application used `path.resolve` which normalizes paths according to the host OS. On POSIX systems, `path.resolve` treats backslashes as regular filename characters, not directory separators. A payload like `subdir/..\..\..\package` bypasses `path.isAbsolute` and `relativePath.startsWith('..')` checks on POSIX, but subsequent code (like stripping or using the ID in vulnerable ways) could be exploited.
**Learning:** Never rely solely on `path.resolve` and `path.relative` for security boundaries when handling paths that might use backslashes on POSIX systems. The mismatch in how different parts of the standard library handle slashes vs backslashes can lead to bypasses.
**Prevention:** Normalize all backslashes to forward slashes *before* any path validation or resolution. Additionally, use a defense-in-depth approach by explicitly rejecting any inputs containing `..` sequences, even if they appear to resolve safely within the base directory.
