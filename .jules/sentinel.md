## 2024-05-24 - Fix Path Traversal Bypass via Backslashes
**Vulnerability:** The application used `path.resolve` and `path.relative` on user-provided note IDs to prevent path traversals. However, on POSIX systems, a backslash (`\`) is considered a regular filename character, so `folder/..\..\etc/passwd` bypassed validation since it resolved as a normal file within the directory. Later, when using the input directly or via `sanitizeNoteId`, the backslashes could be converted into forward slashes, turning it into a valid path traversal payload: `folder/../../etc/passwd`, leading to arbitrary file access/creation outside the designated notes directory.
**Learning:** Normalizing directory separators (e.g., backslashes to forward slashes) MUST happen *before* executing path traversal validation checks. Relying on OS-specific path parsing during validation and then subsequently mutating separators in sanitization logic breaks the validation assumptions.
**Prevention:** Always normalize all backslashes (`\`) to forward slashes (`/`) before passing user input to functions like `path.resolve` and `path.relative` when protecting against directory traversals, ensuring uniform behavior regardless of the underlying OS and preventing validation bypasses in sanitization steps.
