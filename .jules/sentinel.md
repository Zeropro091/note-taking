## 2023-11-20 - Defense in Depth: Explicit Path Traversal Rejection
**Vulnerability:** Path traversal payload 'folder/../../note' incorrectly resolved to a valid ID due to flawed validation logic that allowed relative paths if they resolved strictly inside the directory. Additionally, POSIX-based tools bypassed traversal restrictions via backslashes `\`.
**Learning:** Depending entirely on `path.resolve()` and `path.relative()` to filter `..` relies on OS-specific resolution and assumes all possible traversal encodings are accurately processed without side-effects (like bypassing earlier sanitization checks). The old implementation also allowed `..` inputs to succeed if they ultimately resolved inside `NOTES_DIR`, which is unsafe practice since IDs should never inherently contain traversal segments.
**Prevention:** Always combine multiple defensive measures. First, normalize path separators (e.g., `\` to `/`). Second, explicitly and aggressively block any identifiers that contain traversal syntax like `..`, rather than attempting to safely resolve them. Finally, use `path.relative` verification as a final check, not the sole validation method.
