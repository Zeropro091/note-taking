## 2024-05-18 - [Path Traversal bypass via Backslash Normalization]
**Vulnerability:** The `validateNoteId` function in `src/lib/file-system.ts` allowed path traversal attempts using backslashes on POSIX systems (e.g. `..\\..\\etc\\passwd`), which path.relative might not process correctly as a traversal on Unix depending on how node was run, or allowed tricking of simple regex checks. More importantly, it allowed IDs with `..` that technically resolved within the directory but were highly suspicious.
**Learning:** `path.resolve` and `path.relative` behave differently depending on the operating system regarding backslashes. Relying solely on `path.relative` without first normalizing backslashes, and without explicitly rejecting `..`, leaves a defense-in-depth gap where POSIX-based path traversal bypasses could occur.
**Prevention:** Always normalize backslashes (`\`) to forward slashes (`/`) BEFORE applying path resolution logic, and explicitly reject IDs containing `..` to provide a defense-in-depth barrier against traversal attacks, even if subsequent path functions claim the result is "safe".
