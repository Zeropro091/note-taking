## 2024-05-28 - [Path Traversal bypass fix via File IDs]
**Vulnerability:** The application was vulnerable to path traversal bypasses on Windows or cross-platform environments because backslashes (`\`) could be used to bypass initial validation (if not treated as separators) and were later evaluated by `path.resolve`. Furthermore, it incorrectly allowed sequences containing `..` if they ultimately resolved within the target directory, which could still be manipulated in unforeseen ways.
**Learning:** Always normalize path separators (`\` to `/`) before performing any path validation or resolution. Relying solely on `path.resolve` or `path.relative` checking the output directory is insufficient defense-in-depth, as `..` sequences should simply be outright rejected in user input representing a unique ID or relative path.
**Prevention:** In implementations handling paths derived from user input, explicitly check for and reject any strings containing `..`. Standardize on normalizing backslashes before validation checks begin.
