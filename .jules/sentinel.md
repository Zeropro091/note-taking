## 2025-07-03 - Path Traversal bypass via Windows-style backslashes in POSIX environments
**Vulnerability:** The note ID validator checked against `..` using string prefix and relativity logic via `path.resolve` and `path.relative` on a POSIX system. However, when passed backslashes like `..\\..\\`, these backslashes aren't normalized as path separators in POSIX `path.relative`. Once sanitized (or if used dynamically), this bypasses traversal checks while still escaping out of intended directories when used in FS operations, creating a critical vulnerability.
**Learning:** `path.resolve` and `path.relative` behave differently depending on the host OS. On POSIX, they do NOT treat `\` as a directory separator. This allows Windows-style paths to bypass POSIX path checks.
**Prevention:** Always normalize all backslashes (`\`) to forward slashes (`/`) *before* applying path traversal logic (e.g., `path.resolve`/`path.relative`). Additionally, use regex (e.g. `/(^|\/)\.\.(?=\/|$)/`) to explicitly reject traversal attempts outright rather than relying purely on absolute relativity validation, providing defense-in-depth.
