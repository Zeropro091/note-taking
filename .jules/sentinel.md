## 2024-10-18 - Path Traversal Bypass via Backslashes
**Vulnerability:** The `validateNoteId` function was vulnerable to path traversal bypasses on POSIX systems when users input paths containing backslashes (e.g., `..\..\etc\passwd`). `path.resolve` handles backslashes as valid path characters on POSIX, rather than as directory separators, which caused `path.relative` to misinterpret the path structure and bypass checks. Additionally, `..` strings within valid directories were still considered valid by `path.relative` after resolution.
**Learning:** Checking for traversal by strictly analyzing `path.relative` output is flawed if backslashes aren't normalized first on POSIX environments, or if paths still resolve within the target directory despite containing traversal sequences (`..`).
**Prevention:** Normalize backslashes to forward slashes before resolving paths and explicitly reject any IDs containing traversal sequences (`..`), even if `path.relative` deems them within the expected directory structure.
