## 2024-06-12 - Path Traversal bypass with backslashes
**Vulnerability:** The `validateNoteId` function in `file-system.ts` had a path traversal vulnerability. It didn't account for backslashes `\` being evaluated by Node.js APIs correctly as paths, allowing payloads like `foo/..\\..\\..\\etc\\passwd` to bypass the `path.relative` check on non-Windows systems, and then `sanitizeNoteId` would later convert them to forward slashes, causing an actual path traversal.
**Learning:** `path.resolve` treats backslashes differently on Windows vs POSIX systems, meaning a malicious user can provide paths that seem safe during validation on a POSIX server (because it doesn't see `\` as a folder separator) but are actually traversed later if the app manually replaces `\` with `/` or uses the string in other contexts.
**Prevention:** Always normalize file paths (e.g., replace backslashes with forward slashes) BEFORE validating them and strictly reject input that contains `..` anywhere in the path string as an extra defense-in-depth measure.
