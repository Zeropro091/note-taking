## 2024-06-24 - [Fix Path Traversal bypass with Backslashes]
**Vulnerability:** Path traversal check in `validateNoteId` was vulnerable to bypass because it did not normalize Windows-style backslashes before using `path.resolve` and checking `path.relative`. The check would allow paths like `..\..\` as it doesn't recognize backslashes as path delimiters on non-Windows platforms. Also it didn't explicitly forbid the `..` sequence, relying purely on Node's path resolution which is OS-specific.
**Learning:** `path.resolve` and `path.relative` behave differently depending on the operating system the server is running on. On a Linux server, they do not interpret `\` as a path separator, so `..\\` is treated as a literal filename rather than a traversal sequence, but the underlying file system might handle it differently, or subsequent sanitization might combine to create an issue.
**Prevention:** As a defense-in-depth measure, normalize all backslashes to forward slashes BEFORE performing any path validation or resolution. Always explicitly reject the `..` sequence from IDs. Do not rely solely on `path.relative` when security is at stake.
