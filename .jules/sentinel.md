## 2025-02-27 - Path Traversal bypass via Windows paths
**Vulnerability:** Path traversal defense could be bypassed. The `validateNoteId` function was vulnerable to POSIX traversal bypasses if Windows-style backslashes were used, because `path.resolve` and `path.relative` on POSIX systems (like Linux) do not treat backslashes as directory separators. So a payload like `..\\..\\etc\\passwd` might pass the relative checks but could potentially be processed differently or sent to a component that evaluates backslashes. Furthermore, it allowed `..` if they resolved to a path still within the base directory.
**Learning:** Backslashes need to be normalized to forward slashes BEFORE resolving paths to ensure consistency and prevent POSIX traversal bypasses. Relying solely on `path.relative` and `path.resolve` might not catch `..` if the overall path resolves inside the target folder, but it is safer to explicitly reject `..`.
**Prevention:** Normalize backslashes to forward slashes before any path manipulation. Explicitly reject any input containing `..` as a defense-in-depth measure, alongside `path.resolve` and `path.relative` checks.
