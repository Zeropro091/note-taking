## 2024-06-13 - Path Traversal Bypass via Backslashes
**Vulnerability:** The `validateNoteId` function was vulnerable to a path traversal bypass because it did not reject traversal characters like `..` nor normalize backslashes before calling `path.resolve` and `path.relative`. On non-Windows platforms, `path.resolve` treats backslashes as regular characters instead of directory separators.
**Learning:** Checking for traversal by simply checking if the resolved path is inside the directory can fail if backslashes are used on non-Windows platforms. The path containing `..\\` could bypass typical `..` stripping filters or `relative.startsWith('..')` checks while still being interpretable by the underlying file system APIs or a downstream consumer.
**Prevention:** Always normalize backslashes to forward slashes before any path validation/resolution. Also, as defense in depth, explicitly reject strings containing `..` rather than trying to safely parse them or allowing them if they eventually resolve within the boundary.
