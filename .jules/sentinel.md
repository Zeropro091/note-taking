## 2026-06-01 - Defense in Depth Against POSIX Path Traversal
**Vulnerability:** A path traversal bypass was present in `validateNoteId` where using `..` with forward slashes instead of backslashes could bypass simple regex replacements if not carefully checked, and even if path.relative check caught some things, a robust defense in depth was missing for `..`. Specifically, the path validation allowed strings like `folder/../../note` which, while technically resolving safely within the root after stripping `..` according to `path.relative`, introduces unnecessary risk and violates the principle of least privilege.
**Learning:** `path.resolve` and `path.relative` checks are good, but explicit substring checks for `..` are necessary for defense-in-depth to ensure no traversal attempt is ever allowed, even if it might resolve "safely" within the allowed directory tree. Normalizing all backslashes to forward slashes before any validation ensures consistent behavior across OS environments and prevents POSIX traversal bypasses where backslashes might evade checks but be interpreted by the OS or Node.js.
**Prevention:** Always normalize slashes (`replace(/\\/g, '/')`) BEFORE path resolution. As a defense-in-depth measure, always explicitly reject any string containing `..` rather than relying solely on `path.relative` checking the resolved path.
