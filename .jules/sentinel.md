## 2024-06-22 - [CRITICAL] Path Traversal Bypass using Backslashes on POSIX Systems
**Vulnerability:** A path traversal vulnerability existed in the `validateNoteId` function. On POSIX systems, `path.resolve` treats backslashes as regular filename characters. When an attacker passed a malicious path like `folder\..\..\..\etc\passwd`, `path.resolve` failed to detect the traversal. However, a downstream function (`sanitizeNoteId`) blindly converted backslashes to forward slashes, inadvertently enabling a successful path traversal when the sanitized string was used to construct a path.
**Learning:** Path validation and normalization logic must perfectly align with the specific operations applied downstream. Backslashes can mask malicious directory traversals on POSIX environments during validation steps that use `path` module if the application later normalizes those slashes for internal use.
**Prevention:** Always normalize slashes (e.g. converting `\\` to `/`) *before* executing path validation checks (like `path.resolve` or `path.relative`). Additionally, apply defense-in-depth by explicitly rejecting known dangerous sequences like `..` in normalized path strings.
