## 2024-07-04 - Path Traversal Bypass via Backslashes on POSIX Systems
**Vulnerability:** The `validateNoteId` function in `src/lib/file-system.ts` was vulnerable to a path traversal bypass. It attempted to validate paths by passing them directly to `path.resolve` and `path.relative`. However, on POSIX systems (Linux/Mac), Node's `path` module treats backslashes (`\`) as literal filename characters, not path separators. An attacker could provide a path like `..\\..\\etc\\passwd`, which would pass `validateNoteId` because `path.relative` would see it as a single filename inside the `notes` directory, rather than a traversal attempt. Then, `sanitizeNoteId` replaced backslashes with forward slashes before passing to `getNoteById`, converting the payload into an active path traversal payload (`../../etc/passwd`), thus achieving arbitrary file read/write (since the output of `sanitizeNoteId` bypassed the previous validation logic).
**Learning:** This highlights a dangerous discrepancy between path resolution engines (POSIX vs Windows) and string normalization logic. If you validate a path *before* normalizing backslashes to forward slashes, an attacker can use backslashes to slip POSIX-invalid paths past the check, which then become active traversals once normalized. Additionally, trying to be clever with path validation relying purely on `path.resolve` and `path.relative` can fail if the input doesn't use the expected path separators.
**Prevention:** Always normalize path separators (`id.replace(/\\/g, '/')`) *before* applying path validation logic (like `path.resolve` or `path.relative`). As a defense-in-depth measure, add an explicit regex check for bounded traversing tokens (`/(^|\/)\.\.(?=\/|$)/`) to proactively block them rather than relying purely on Node.js `path` utilities.
