## 2023-10-27 - Path Traversal Bypass via POSIX Backslash Handling
**Vulnerability:** A path traversal bypass was found in the `validateNoteId` function. It checked for `..` in the resolved relative path, but did not normalize backslashes beforehand. On POSIX systems, backslashes are treated as valid filename characters by `path.resolve`. This allowed an attacker to pass a payload like `foo/..\..\..\etc\passwd`, which bypassed the `..` check during validation. Later, the `sanitizeNoteId` function converted these backslashes to forward slashes, enabling the path traversal.
**Learning:** Path traversal protections that rely on `path.resolve` and `path.relative` on POSIX systems can be bypassed if the input contains backslashes (`\`) intended for directory traversal on Windows. Subsequent normalization (like converting `\` to `/`) after validation can re-introduce the traversal.
**Prevention:** Always normalize path separators (e.g., converting `\` to `/`) *before* resolving and validating paths.
