## 2024-05-25 - Path Traversal Vulnerability via Backslashes

**Vulnerability:** The `validateNoteId` function in `src/lib/file-system.ts` used `path.resolve` and `path.relative` to prevent path traversal, but it did not normalize backslashes to forward slashes before resolving on POSIX systems. This allowed an attacker to bypass the validation using paths like `foo\..\..\..\etc\passwd`, which `path.resolve` treats as a single valid filename on Linux/Mac, but the subsequent `sanitizeNoteId` function replaced `\` with `/` and passed the traversed path to file system operations.
**Learning:** `path.resolve` behavior depends on the OS. On POSIX systems, `\` is a valid character in filenames, not a directory separator. When standardizing paths that might contain backslashes for path traversal prevention, you must normalize `\` to `/` before using `path.resolve`, especially if downstream code or the OS itself might interpret those normalized paths as directories.
**Prevention:** Always normalize backslashes to forward slashes (`id.replace(/\\/g, '/')`) before validating paths with `path.resolve` and `path.relative` to ensure consistent path resolution behavior regardless of the underlying operating system.
