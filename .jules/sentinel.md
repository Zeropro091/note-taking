## 2024-07-06 - POSIX Path Traversal Bypass via Unnormalized Backslashes
**Vulnerability:** Path traversal checks in `validateNoteId` were vulnerable to a POSIX bypass because backslashes (`\`) are not treated as directory separators by `path.resolve` on POSIX systems. An input like `foo/..\..\etc\passwd` would bypass the `startsWith('..')` check after resolution, but then get interpreted as directory traversal when stripped of `..` by a flawed sanitizer, allowing access to files outside the intended directory.
**Learning:** `path.resolve` behaviour differs between operating systems. Security controls relying on path manipulation functions must account for these differences. On POSIX, backslashes in paths can bypass directory validation if not explicitly handled or normalized before resolution. Furthermore, allowing traversal elements (`..`) and relying on "safe stripping" is inherently dangerous.
**Prevention:** Normalize all backslashes to forward slashes before any path validation or resolution. Use a defense-in-depth approach by explicitly rejecting traversal attempts (e.g., `/(^|\/)\.\.(?=\/|$)/`) before relying on `path.resolve` and `path.relative` to ensure paths remain bounded.
