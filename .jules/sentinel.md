## 2024-05-24 - [Path Traversal bypass via post-validation sanitization]
**Vulnerability:** A path traversal vulnerability existed in `validateNoteId` where Windows-style path traversal patterns using backslashes (e.g. `somefolder\..\..\etc\passwd`) bypassed validation on POSIX environments because `path.resolve` treats backslashes as regular filename characters. The subsequent `sanitizeNoteId` function would then incorrectly normalize these backslashes into forward slashes *after* validation but *before* file system interaction, leading to an exploitable traversal.
**Learning:** Normalizing backslashes to forward slashes must occur *before* validation (such as `path.resolve`) to ensure that the environment's path resolution mechanisms accurately interpret the sanitized and finalized file path, thus preventing POSIX bypasses.
**Prevention:** Always normalize path separators to a consistent format (e.g. forward slashes) as the absolute first step in path validation and resolution logic, prior to making any directory boundary checks.
