## 2024-03-24 - [Fix Path Traversal Bypass via Backslash and Embedded Traversal]
**Vulnerability:** Path traversal bypass in `validateNoteId` where `path.resolve` correctly evaluated paths with mixed slashes, but backslashes allowed bypassing simple POSIX trajectory strings (e.g., `..\` on Windows bypassing `../`). Additionally, embedded traversals like `folder/../../` were allowed if they resulted in a path within `NOTES_DIR`, which is a risky pattern.
**Learning:** `path.resolve` normalizes paths, so `..` and `\` and `/` interact in ways that might bypass simple string checks or `path.relative` depending on the environment. Allowing embedded `..` inside a path just because the final path is within the base directory is dangerous because the underlying filesystem might handle the unresolved string differently, or the initial implementation might have stripped the `..` resulting in `folder///note` instead.
**Prevention:** As a defense-in-depth measure, normalize all backslashes to forward slashes before any `path.resolve` or `path.relative` operations. Explicitly reject any input string containing the `..` sequence, rather than trying to sanitize it or relying on `path.resolve` to safely resolve it to an allowed directory. Always explicitly reject any string containing `..`.
