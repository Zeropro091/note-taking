## 2024-06-20 - POSIX Path Traversal Bypass via Backslashes
**Vulnerability:** A path traversal vulnerability existed in `validateNoteId` where a Windows-style path traversal attempt (e.g., `subdir/..\\..\\..\\etc\\passwd`) could bypass the `path.relative` check when running on a POSIX system, allowing access to arbitrary files outside the intended directory.
**Learning:** `path.resolve` and `path.relative` behave differently depending on the operating system. On POSIX systems, backslashes (`\`) are treated as valid filename characters, not path separators. Therefore, Windows-style path traversal payloads using backslashes are not properly resolved and can bypass naive checks that rely solely on `path.relative`.
**Prevention:** To prevent this, backslashes must be explicitly normalized to forward slashes *before* any path resolution or validation checks are performed. Additionally, as a defense-in-depth measure, any IDs containing `..` should be explicitly rejected, even if they appear to resolve safely within the base directory.
