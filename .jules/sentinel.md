## 2024-05-24 - Path Traversal Bypass via OS-Specific Separators and Implicit Resolution
**Vulnerability:** The `validateNoteId` function was relying on `path.resolve` and `path.relative` to prevent path traversal. However, it was missing an explicit rejection of `..` sequences and failed to normalize Windows backslashes (`\`) before processing. This combination could allow an attacker to bypass validation if the resulting string appeared safe to Node's `path` functions but was interpreted differently by underlying OS/filesystem layers.
**Learning:** Defense in depth is required for path validations. Built-in path resolution libraries are robust but might have OS-specific quirks when evaluating unsanitized inputs. Relying solely on the resolution output (e.g. `path.relative` not starting with `..`) is insufficient if intermediate directories cancel out `..` sequences, which can still represent an intent to traverse paths.
**Prevention:** Normalize backslashes (`\`) to forward slashes (`/`) *before* evaluating or resolving paths to prevent POSIX traversal bypasses. Explicitly reject any inputs containing `..` sequences as a strict defense-in-depth measure, even if the sequences would theoretically resolve safely within the base directory.
