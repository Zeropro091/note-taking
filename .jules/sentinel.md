## 2025-06-17 - File System Path Traversal Bypass via OS Differences
**Vulnerability:** The application was vulnerable to path traversal because it relied on Node's `path.resolve` and `path.relative` for validation without normalizing paths first. Specifically, Windows-style paths like `..\\etc\\passwd` were evaluated incorrectly on POSIX environments because backslashes `\` aren't native path separators there, allowing traversal characters to evade the simple validation logic while `path.resolve` might still process them maliciously in certain contexts. Also, paths containing `..` that coincidentally resolved "inside" the target directory using `path.relative` were allowed, violating defense-in-depth principles.
**Learning:** You cannot solely rely on OS-specific path resolution algorithms like `path.relative` when user input could contain path separator semantics from a different operating system (e.g., Windows backslashes on a Linux server).
**Prevention:** Always normalize path separators (e.g. replacing `\\` with `/`) *before* executing any path traversal validation. As a defense-in-depth strategy, explicitly reject inputs containing known traversal sequences like `..` rather than trusting `path.resolve` to safely handle or strip them.
