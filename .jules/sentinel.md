## 2025-02-27 - Path Traversal POSIX Bypass in ID Validation
**Vulnerability:** A path traversal vulnerability where IDs containing Windows-style slashes (`\`) could bypass POSIX path validation (like `path.resolve` and `path.relative` on non-Windows environments) when the final operation is executed or if `id` contained strings like `..` that technically resolved back within the base directory (e.g., `folder/../../note`).
**Learning:** Checking for traversal by relying solely on checking `path.relative` for `..` is insufficient if the raw input contains path traversal characters like `..` or unnormalized slashes. Windows slashes (`\`) are not interpreted as directory separators in Linux environments but could be parsed later down the stack. Explicit string containment checks and early normalization are necessary for true defense-in-depth against payload evasion.
**Prevention:** Always normalize backslashes to forward slashes before doing path resolution (`id.replace(/\\/g, '/')`). As a defense-in-depth measure, explicitly reject any IDs containing `..` via `id.includes('..')` before they are processed by standard path utilities.
